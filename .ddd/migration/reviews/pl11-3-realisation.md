# PL11-3 : médecins (table `medecin`) dans l'Organisation : ÉTAT EXACT

## Fait (compile ; tests Organisation verts : GererLesMedecinsTest 8, GererLesCreneauxTest 9, OrganisationServiceTest 14, MedecinTest 3, ArchitectureHexagonaleTest 10)
- Organisation domaine : `SaisieDeMedecin` (VO : nom obligatoire, 3 champs <= 255, nettoyage espaces/insécable, vide = absent), `SaisieDeMedecinInvalide`, `MedecinDejaExistant`, `Medecin` (+ `corriger`, `reactiver`, `cle`, `verifierLUnicite`), `MedecinRepository` (+ `listerTousParCentre`, `page`).
- Clé d'unicité EXACTE (D7, règle de l'admin) : `nom|prenom` normalisés (trim, espaces multiples réduits, minuscules ; accents CONSERVÉS ; prénom absent/vide = chaîne vide), par centre, parmi les médecins ACTIFS. Cas limites reproduits : même nom sans prénom <> même nom avec prénom ; l'import sans colonne prénom ne retrouve pas un médecin qui a un prénom (doublon de nom créé) ; un médecin du centre B n'empêche pas le centre A.
- Application : `GererLesMedecins` (créer / modifier / désactiver / lister / proposes / importer + `ajuster` et `desactiverSansEchec` pour la route d'Organisation) ; `ReferentielsOrganisationService` délègue les 3 méthodes médecin à `GererLesMedecins`.
- Langage publié : `GestionDesMedecins`, `RefusDeMedecin`, `DescripteursDeLOrganisation.MEDECIN` ; bean `gestionDesMedecins` (OrganisationConfiguration) ; `MedecinsJdbc` (+ page SQL identique à l'ancien adaptateur : recherche nom/prénom/spécialité, tri nom, prénom, id).
- Route d'Organisation : même unicité (D7) : doublon -> 422 `MEDECIN_DEJA_EXISTANT` (nouveau code, détail dans `ErreursDeLOrganisationAdvice`) ; création d'un nom désactivé -> réactivation (D6, renvoie l'id existant) ; modification partielle conservée (champ absent conservé, médecin désactivé modifiable) mais avec contrôle d'unicité ; 2e désactivation = 200 (inchangé) ; nom absent -> 400 "Nom requis" (inchangé).
- Plateforme : ACL `acl/organisation/MedecinsParOrganisation` ; `ReferentielsDeLOrganisation.MEDECIN` ; `ReferentialKind.MEDECIN` et l'entrée `ReferentialAdminTables` retirés ; `ReferentialAdminJdbcAdapter` : SQL médecin retiré (actifSeulement, UPDATE actif), `findAllForMatching(MEDECIN)` via `GestionDesMedecins#proposes` ; `PatientMigrator` utilise `ReferentielsDeLOrganisation.MEDECIN` ; `DomainServiceConfig` (bean + liste des délégués). `HistoryRules` n'apparie aucun médecin (FORFAIT seulement) : rien à changer.
- Test d'architecture : `LaFacadeDesReferentielsNeDecritQueLesReferentielsEncoreDirectsTest` (7 verts) : seule SALLE reste directe ; regex anti-retour étendue à `ReferentialKind.MEDECIN` ; nouveau test `l_administration_generique_n_ecrit_ni_ne_lit_plus_la_table_medecin` (aucun `from/update/into/join medecin`, `"medecin"`, `medecin_`, `ReferentialKind.MEDECIN` dans ReferentialAdminTables/adaptateur, et `MEDECIN` absent de ReferentialAdminTables).
- covered.json : 1 nouveau fichier de plateforme inscrit : `backend/platform/src/main/java/com/hemodialyse/backend/infrastructure/acl/organisation/MedecinsParOrganisation.java`. Aucun fichier legacy existant non couvert n'a été bloquant (les éditions de ReferentialKind, ReferentialAdminTables, ReferentialAdminJdbcAdapter, PatientMigrator, DomainServiceConfig ont été acceptées par le hook).
- PL11-5 : avancement partiel, comme pour les créneaux : l'appariement des médecins de `PatientMigrator` passe par le port publié `GestionDesMedecins#proposes` (via `findAllForMatching`). Reste pour PL11-5 : retirer `findAllForMatching` lui-même (salles, puis ses autres usages).

## Décisions / écarts à signaler
1. D3 / D10 (ports d'usage par propriétaire) NON implémentés pour les médecins, volontairement : D5 autorise la désactivation d'un médecin utilisé, donc plus aucun refus fondé sur l'usage ; un comptage n'aurait aucun effet (la désactivation est logique et le reste, KB-ORG-03 : 1 ligne conservée). Aucune erreur de contrôle d'usage possible = pas de cas D10. Les usages (`patients.medecin_traitant_id`, `prescriptions_medicales.medecin_id`, `ordonnances.medecin_id` varchar, séances) ne sont plus interrogés. A CONFIRMER par l'utilisateur : si un comptage informatif est voulu (ex. message "N références"), c'est un ajout de 3 ports `UsageDuMedecin` (Patient, Dossier médical, Séance) sur le modèle de PL11-2.
2. Cache `ref.medecins` : l'écriture d'administration vide désormais tout le cache des listes médecins (comme la route d'Organisation, `MedecinsJdbc.sauvegarder`), alors qu'avant elle ne vidait que le centre. Conséquence : golden `cache-des-medecins` change (B relu = rechargé) ; sans effet fonctionnel.
3. Route d'Organisation : valeurs nettoyées à la création (espaces, vide = null) comme l'admin (avant : stockées brutes). Conséquence de D7.
4. Réactivation (D6) : la saisie remplace nom/prénom/spécialité du médecin réactivé (comme les créneaux).
