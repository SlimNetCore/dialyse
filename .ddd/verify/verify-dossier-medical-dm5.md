## Points vérifiés conformes
1. **Parité** : 32 goldens `*_nouveau_code` (antécédents 12, allergies 10, abords 10), tous en `R100` vers `_ecarts-legacy/**` (rename sans modification : identiques octet pour octet à `531ae309`, `git diff -M`). Aucun golden d'origine ou hors DM5 modifié (le diff ne touche que `dm5/**`) ; goldens FHIR de DM5 et filet CATHETER Planification inchangés. Chaque écart `_nouveau_code` est annoté dans le test (KB-MED-58/59/60/61/62/63/64) et consigné dans `known-bugs.md` § Décisions DM5 (KB-MED-58 à 71 tous présents, une décision chacun). L'assertion d'abords « centre B vide » → « 1 ligne » est légitime : elle découle directement de KB-MED-62 (le PUT du centre A ne réaffecte plus l'abord du centre B), commentée dans le test et documentée dans l'ADR/known-bugs.
2. **Sécurité** : `@PreAuthorize` sur chacune des routes des 3 contrôleurs (lecture MEDECIN/ADMIN, abords + INFIRMIER ; écritures MEDECIN, KB-MED-69 reproduit). 403 avant 400 géré dans l'advice (corps lu avant `@PreAuthorize`). Patient inconnu/autre centre → 404 `PATIENT_INTROUVABLE` à l'écriture (`EnregistrerUnAbordVasculaire`). PUT abord : `trouverEnVerrouillant(centre, patient, id)` puis `UPDATE … WHERE id AND center_id AND patient_id` : ni upsert ni réaffectation (inter-patients et inter-centres couverts par goldens `upsert_et_deplacement_nouveau_code`, `cloisonnement_nouveau_code`). SQL des trois adapters toujours filtré par `center_id`. Messages d'erreur génériques ; WARN = identifiant seul. 409 via SQLSTATE 55P03 (`VerrousJdbc.verrouille`) ; ordre de verrous documenté centre → fiches → app_user → consultatifs, fiche verrouillée avant le verrou de diagnostic.
3. **DDD** : le domaine n'importe que java.util/time/math ; pas d'`Instant.now`/`UUID.randomUUID` (horloge via `HorlogeDuCentre`, identifiants via `GenerateurDIdentifiants`). `CodeClinique` est un record validé (forme CIM-10/LOINC, normalisation, bornes), égalité par système+code. Listes fermées (`TypeDAntecedent`, `StatutClinique`, `CriticiteDAllergie`…) : le legacy les désérialisait en enum (hors liste → 500), désormais 400 sans nom interne, mêmes valeurs acceptées. Agrégats à comportement (pas de setters), un agrégat par transaction, port = racine. Patient via ACL `PatientsDuCentre`. Aucune façade, aucun flag, aucun événement inventé (KB-MED-67).
4. **Legacy** : `covered.json` : 163 entrées, 0 chemin absent ; `seamAllowed` = [] ; les 19 entrées mortes retirées ; `DomainServiceConfig` allégé de 3 beans ; classes conservées avec consommateurs réels (FHIR, `GreffePdfService`, import/rollback) ; jalon 2026-12-15 présent dans l'ADR, `seams.md` et la fiche.

6. **Lignes illisibles** : ignorées + WARN, figées par les contrats JDBC, §49 q.6 les repère (SELECT seule) ; code relu en majuscules sans re-validation (`CodeClinique.reconstituer`).
7. **PostgreSQL** : script cohérent (aucune colonne ni contrainte ajoutée, pas de table parallèle, 8 requêtes §49 SELECT seule exécutées), contrats verts.
