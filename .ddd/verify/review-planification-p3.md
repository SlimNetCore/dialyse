## Points examinés sans écart

- **(a) Comportement.** 35 goldens changent par décision (28 modifiés, 7 renommés). Les anciens comportements sont
  conservés dans `_ecarts-legacy` (35 fichiers). Les 5 scénarios « adaptés » sont légitimes : une décision a rendu leur
  prémisse illégale (chevauchement d'absences, infirmier désactivé, remplacé non concerné, auteur de l'absence,
  diffusion du retrait). La propriété observée est conservée, avec la réserve du constat 3.
- **(c) Concurrence.** Une seule fiche est verrouillée par transaction P3. Le verrou du centre porte sur
  `planning_parametres` ; le verrou du référentiel P2 (`FOR NO KEY UPDATE` sur `centers`) est compatible avec le
  `KEY SHARE` posé par les clés étrangères des insertions P3. P3 ne verrouille pas `app_user`, et `declaree_par` n'a pas
  de clé étrangère. **Aucun cycle d'interblocage n'a été trouvé** avec P1, P2 ou `UserRestController`. La dette
  KB-PLN-40 n'est acceptable jusqu'à P8 qu'une fois le constat 1 traité ou explicitement accepté.
- **(d) Dates.** Les règles sont identiques au legacy : 366 jours (`DAYS.between + 1`, années bissextiles comprises),
  `ABSENCE_PASSEE` si fin < aujourd'hui, `ABSENCE_NON_ANNULABLE` si début ≤ aujourd'hui, remplacement refusé si date <
  aujourd'hui (aujourd'hui inclus accepté). `HorlogeDesCentresLegacy` revient à `Africa/Algiers` si le fuseau est nul,
  blanc ou illisible.
- **(e) Migration V47.** `ADD COLUMN IF NOT EXISTS … UUID` nullable, sans défaut ni index : modification de métadonnées
  seule sur PostgreSQL, valide sur H2 2.x. `schema.sql` et le schéma H2 des tests sont alignés.
- **(f) Frontières.** `PresenceDonneesJdbcAdapter` ne lit plus les 3 tables, seulement le langage publié. Le format
  `jours` est identique à celui du legacy, et les 4 ACL sont dans `platform/.../acl/planification/`.
- **(h) Documentation.** RG-INF-031/032 (`10-infirmiers.md:95-113`), ADR 0057, KB, § 34 et roadmap sont cohérents entre
  eux.
